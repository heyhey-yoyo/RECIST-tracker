# CLAUDE.md

This file provides guidance to Claude Code when working with this repository.

## Project overview

RECIST Tracker is a **pure client-side SPA** (Single Page Application) for tumor response assessment per RECIST 1.1 and iRECIST. It targets deployment on Cloudflare Pages or Cloudflare Workers Static Assets. There is no backend, no framework, and zero runtime dependencies — everything is vanilla JavaScript ES modules.

## Build and test

```bash
npm run test       # Node.js built-in test runner; tests are in tests/
npm run build      # copies public/ + src/ into dist/ (script: scripts/build.mjs)
npm run check      # test + build
npm run preview    # serves dist/ on http://localhost:4173 via Python http.server
```

Requires **Node.js ≥ 20**. The build script is a simple file-copy pipeline with `node:fs/promises` — no bundler, no minifier.

## Architecture

### State management

All application state lives in a single `state` object (`src/app.js:26`):

```js
state = {
  schemaVersion: 1,
  settings: { studyName, protocol, assessor, defaultMode },
  patients: [ ... ],
  audit: [ ... ]
}
```

- **Persistence**: `loadState()` / `saveState()` read/write `localStorage` under key `recist-tracker-state-v1`.
- **Audit**: Every mutation calls `appendAudit()` with `{ action, entityType, entityId, patientId, summary, before, after }`. Max 2000 entries.
- **State normalization**: `normalizeState()` in `model.js` ensures backward compatibility — always call it after loading.

### Routing

Hash-based routing in `src/app.js`:
- `#/patients` — patient list (default)
- `#/patient/:id/overview` — overview with timeline
- `#/patient/:id/lesions` — lesion management
- `#/patient/:id/visits` — visit entries
- `#/patient/:id/audit` — audit log
- `#/settings` — study settings
- `#/backup` — data backup/restore
- `#/about` — rule boundaries

### UI pattern

The entire UI is server-side-style HTML template strings rendered via `app.innerHTML = ...`. There is no virtual DOM or component framework.

- `render()` is the main entry point: dispatches to page renderers based on route, then sets `app.innerHTML`.
- Modals are managed via `ui.modal` state; rendered inside the same `render()` pass.
- Toast notifications use the same pattern (`ui.toast`).
- All event handling goes through delegated listeners on `app` (click, change, submit), checked by `data-action` attributes.
- Form data is read via `new FormData(form)` and dispatched by `form.dataset.form`.

### Domain logic

**RECIST 1.1** (`recist.js`):
- `evaluateTargetLesions(patient, visit, previousVisits)` — returns `{ code, currentSum, baselineSum, nadirSum, baselineChangePct, nadirChangePct, reason }`
- `evaluateNonTargetLesions(patient, visit)` — returns `{ code, reason }`
- `evaluateOverallResponse({ target, nonTarget, hasDefiniteNewLesion })` — combines target + non-target + new lesions
- `evaluateRecistSequence(patient)` — processes all visits chronologically, returns array of per-visit results

**iRECIST** (`irecist.js`):
- `evaluateIrecistSequence(patient)` — sequential state machine over `evaluateRecistSequence()` results
- Tracks `pending` iUPD anchor; confirms iCPD when further progression criteria met (5 mm increase, non-target further increase, additional new lesions)
- Resets iUPD to iCR/iPR/iSD if no confirmation and lesions improve
- Emits warnings for confirmation window violations (not within 28–56 days) and clinical instability

### Key constraints encoded in validation (`validation.js`)

- Max 5 baseline target lesions, max 2 per organ
- Max 5 definite new target lesions, max 2 per organ
- Lymph node: baseline short axis ≥ 15 mm for measurability (warning)
- Non-lymph node: baseline longest diameter ≥ 10 mm for measurability (warning)
- Visit dates must not precede baseline date
- No duplicate visit dates

## Code conventions

- **Language**: Chinese for user-facing strings and comments; English for identifiers.
- **Module system**: ES modules only (`import`/`export`), no bundler required.
- **No dependencies**: The project intentionally has zero npm dependencies. Do not add any without explicit approval.
- **Factory functions**: Use `createPatient()`, `createVisit()`, `createInitialState()` from `model.js` rather than constructing objects manually.
- **Cloning**: Use `clone()` from `model.js` (JSON round-trip) for deep copies before audit logging.
- **IDs**: Use `createId(prefix)` which generates `prefix_uuid` via `crypto.randomUUID()`.
- **Date handling**: Store dates as `YYYY-MM-DD` strings. Use `daysBetween()` from `format.js` for interval calculations. Use `nowIso()` for timestamps.
- **Immutability in audit**: Always capture `clone(before)` before mutation and `clone(after)` after mutation for audit entries.
- **Test style**: Node built-in test runner (`node:test` + `node:assert/strict`). Tests import domain logic directly.

## Important boundaries

- This is a **medical assessment aid**, not a regulated medical device. It has no GxP / 21 CFR Part 11 validation.
- All data stays in the browser. There is no backend, no authentication, no multi-user support.
- The app deliberately excludes: image viewing, Excel/PDF export, print layouts, and multi-center collaboration.
- Manual review is always required for: lesion malignancy determination, unequivocal progression of non-target lesions, lesion splitting/fusion, local therapy, bone/cystic lesions, and protocol-specific modifications.
- When modifying RECIST/iRECIST rules, always add corresponding test cases.
- The `dist/` directory is build output but is currently committed for reference. The build script deletes and recreates it on each run.
